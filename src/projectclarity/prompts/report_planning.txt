Choose the report format from the user's question and clarified requirements, before evidence is collected. Explain why this format answers the request. Do not select a format because it is easier to fill or because of imagined search results.

Use directory for a list of distinct items with requested details. Use entity_profile for an account of one named company, person or organization. A profile identifies the requested subject, its kind, and the scope or distinguishing information actually supplied by the user. If no further identity qualifier is supplied, set subject_scope to null; do not invent headquarters, occupation, dates or identity details. Relationships and projects can be sections of a profile without becoming separate target entities.

Comparison, timeline and topic_overview are recognized but not implemented. If one is necessary for the user's request, select it honestly; the application will explain that it is unavailable instead of silently substituting a directory. A profile may include history, but a request primarily for a chronology is a timeline. For non-profile formats, normally set subject, subject_kind and subject_scope to null; put the requested population and constraints in the research question and requirements. If these fields contain population metadata, they do not change the selected report_type or turn a list into a single-entity profile.

During clarification, ask about materially ambiguous report intent or subject identity using ordinary language. Do not ask the user to choose internal format labels or supply facts the research should discover. During refinement, update the choice and subject using the actual clarification answers, even if this changes the earlier choice. A report plan describes requested scope, not independently verified facts.

A named company with requested topics is already a profile request. Do not ask whether the user wants a detailed profile or a general overview, and do not ask which topics to prioritize when they already listed them. Ask about identity only when there is a concrete ambiguity that would change the target, not merely because subject_scope is null.
